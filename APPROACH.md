# Approach

I prioritised the author-to-operations ticket loop: seeded author data, role-based access, query submission, triage, a human-reviewed response, and near-real-time visibility back in the author portal. The book dashboard preserves the provided edge cases, including in-production titles, null publication/pricing fields, zero payouts, and pending royalties.

AI is a server-side assistant rather than an automatic decision-maker. A compact prompt classifies each new query and estimates urgency; a second category-specific prompt uses the relevant BookLeaf policy when an operator explicitly requests a reply draft. The operator can edit every draft and override category, priority, and status. If the model key is absent or the provider fails, ticket creation still works using local rules and a Knowledge Base-informed response template. This keeps the core workflow usable while avoiding unnecessary model calls and sending only the current query and relevant book context.

For the five-day scope, I chose Create React App with React, Express, and a small atomic-write JSON store rather than requiring database setup. Seven-second polling provides responsive updates with less operational setup than a WebSocket service. The trade-off is that local persistence is single-process and the seeded credentials are demonstration-only; neither is a production deployment strategy.

Given more time, I would move accounts, books, tickets, messages, and notes into PostgreSQL with migrations and audit history; move local demo attachments into malware-scanned object storage; add secure account provisioning and password reset, rate limiting, role/permission management, and a transactional notification/outbox system; replace polling with authenticated server-sent events; and add AI evaluation/feedback, prompt versioning, provider budgets, and observability. I would then deploy the API, database, and static client with managed secrets and HTTPS, and verify authorization and ticket lifecycle behavior through automated integration tests.
